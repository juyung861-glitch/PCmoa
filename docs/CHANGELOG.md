# PCmoa 변경 기록 (v0.2 → v2.6)

## v2.7 — GPT·Gemini 키 지원 · 완전 삭제 명령 · 사용자 가이드
- **AI 명령을 AI 대화로 합침**: 위쪽 ✦ 버튼은 새 AI 대화를 연다(체크한 PC 이름을 미리 적어 줌). 예전 AI 명령 창과 `/api/ai/plan`은 없앰.
- AI 대화에 Claude 말고도 **OpenAI GPT(sk-…)·Google Gemini(AIza…) 키**를 쓸 수 있다. 키 모양으로 서비스를 자동 판별하고, 키별로 서비스·모델·사용량을 따로 기록. 대화 형식(도구 호출·캡처 이미지)은 서버가 각 서비스 형식으로 바꿔 보낸다.
- 연결 프로그램 `--uninstall`: 자동 시작 해제(레지스트리 Run·작업 스케줄러 / systemd 사용자 서비스) → 실행 중인 연결 프로그램 종료 → agent.json 삭제. 남은 폴더 위치를 알려 준다.
- 연결 페이지·설치 스크립트·방화벽 예시의 "PC Manager" 표기를 PCmoa로 정리.
- docs/USER_GUIDE.md: 실제 화면으로 설치·연결, 기능별 사용법, 연결 해제·삭제, 문제 해결, 권한별 기능, 보안, Windows/Linux 안내.


외부 접속이 막힌 망에서 같은 대역 PC를 한곳에서 관리하고 원격으로 조종하는 웹 대시보드 (에이전트 · SSH · AI 대화 · 화면 보기)

같은 대역 LAN 안의 PC들을 한 화면에서 보고(상태 3단계), 추가하고, 메인 PC를 지정하고,
**명령 실행·파일 전송**(에이전트 경로 / SSH 경로)을 하는 웹. 외부 서버 없이 메인 PC 한 대가 서버가 된다.

```
pcmoa/
├─ server/app.py            FastAPI 서버
├─ server/static/index.html 대시보드 (단일 파일)
├─ server/config.json       첫 실행 시 생성: 에이전트 등록 토큰, 서명 키, 암호화 키
├─ server/uploads/          전송용 파일 보관
├─ server/api_keys/         계정별 API 키 (암호화, Git 제외)
├─ agent/agent.py           각 PC 에이전트 (Windows/Linux 공통)
└─ requirements.txt
```

## v2.6 — 터미널 셸 고르기 (Linux 명령어)
에이전트 PC의 터미널 창 위쪽에서 셸을 고른다. 그 PC에 실제로 있는 것만 보인다(연결 프로그램이 한 번 찾아서 알려 줌).
- Windows: PowerShell · 명령 프롬프트(CMD) · **Linux (WSL · 배포판)** · Git Bash
- Linux: bash · zsh · sh
- 바꾸면 그 셸로 바로 다시 연결, 마지막으로 고른 셸은 PC마다 기억. Linux 계열은 `user@host:~$` 프롬프트와 Tab 자동완성.
- WSL이 없는 Windows PC에서 Linux를 쓰려면 그 PC에서 관리자 PowerShell로 `wsl --install` 후 재부팅(그 뒤 연결 프로그램을 다시 켜면 목록에 나타남).
- 여전히 줄 단위 중계라 vim·top 같은 전체 화면 프로그램은 제한(SSH 경로는 진짜 터미널).

## v2.5 — 라이트 모드
사이드바 아래 [시스템 · ☀ 라이트 · ☾ 다크]. 기본은 Windows 설정을 따라가고, 고른 값은 브라우저마다 기억한다(화면 창 등 다른 창도 같이 바뀜).
라이트는 밝은 파스텔 톤. 터미널과 원격 화면 바탕은 내용이 잘 보이도록 두 모드 모두 검정으로 둔다.

## 바로가기 (Windows) — 명령어 없이 켜기
- `make_shortcut.bat` 더블클릭 → 바탕화면에 **PCmoa** 아이콘 생성. `make_shortcut.bat auto`로 실행하면 PC를 켤 때 서버도 자동 시작.
- 바탕화면 **PCmoa** 더블클릭 → 서버를 최소화 창으로 켜고(이미 켜져 있으면 생략) 대시보드를 연다. `.venv`가 있으면 그 Python을 쓴다.
- 서버를 끄려면 작업 표시줄의 "PCmoa 서버" 창을 닫는다.
- 앱 창으로 쓰기: Chrome/Edge에서 대시보드를 연 뒤 주소창 오른쪽 [앱 설치] → 작업 표시줄에 고정.

## v2.4 — 최적화 점검
같은 조건(에이전트 1대, 1600×900 화면)에서 측정한 전/후:
| 항목 | 전 | 후 |
|---|---|---|
| 화면 보기 중 서버 요청(약 50초) | 989 | 219 |
| 화면 보기 중 에이전트 CPU(화면 변화 없음) | 13.5% | 3.7% |
| 화면 보기 중 서버 CPU | 6.2% | 1.9% |
| 대시보드 열어 둠 40초 동안 /api/groups | 18회 | 2회 |
| 지킴이 메모리 | 32.6MB | 18.8MB |
- 화면: 그대로면 그림 대신 '그대로' 신호만 보냄, 1초 넘게 변화 없으면 약 3fps로 낮춤(바뀌거나 조종하면 바로 8fps).
  보는 쪽은 새 그림이 생길 때만 받아 간다(서버가 최대 1.5초 기다렸다 응답) — 같은 그림을 두 번 받지 않는다.
- 에이전트: psutil·mss·pillow는 쓸 때 불러옴. 지킴이는 무거운 모듈을 불러오기 전에 시작.
  GPU 측정은 대시보드를 보는 사람이 있을 때만(Windows에서 PowerShell을 10초마다 띄우던 비용 제거).
- 서버: PC 목록을 보낼 때마다 하던 LAN 주소 조회를 1분 캐시. 그룹 목록은 PC 구성이 바뀔 때만 다시 받음.
- 유휴 상태: 서버 약 83MB·CPU 0.3%, 에이전트 약 29MB(+지킴이 19MB)·CPU 0%.

## v2.3 — 파일 탐색·가져오기 (그 PC → 메인 PC)
카드의 "파일"(또는 화면 창의 [파일]): 그 PC의 폴더를 둘러보고(드라이브 선택·상위·사용자 폴더·경로 입력) 파일은 [받기], 폴더는 [zip 받기]로
지금 보고 있는 브라우저 PC에 내려받는다. 한 번에 4GB까지, SHA-256으로 손상 확인. 서버에는 하루만 임시 보관(그 뒤 자동 삭제).
파일 창을 연 동안에는 그 PC가 0.3초마다 응답해 목록이 바로 뜬다. 자기 계정 PC만, 내려받기는 활동 로그(file_pull)에 남는다.
(반대 방향 — 메인 PC → 그 PC — 는 기존 "명령" 창의 파일 보내기)

## v2.2 — 연결 프로그램 지킴이 · 화면을 새 창으로
- **지킴이**: 연결 프로그램이 오류로 꺼지면 3초 뒤(반복되면 점점 길게, 최대 60초) 자동으로 다시 시작. 활동 로그에 "agent_restart"와 이유가 남고,
  자세한 오류는 그 PC의 `agent.log`. 메인 PC 서버가 아직 안 켜졌거나 재시작 중이어도 꺼지지 않고 연결될 때까지 기다린다.
- Windows 콘솔 '빠른 편집'을 꺼서, 연결 창을 클릭해도 프로그램이 멈추지 않는다(전에는 Enter를 눌러야 다시 움직였음).
- 창 출력은 따로 도는 쓰레드가 맡아, 창이 멈춰도(글자 선택 등) 연결은 계속된다. 그래도 2분 넘게 진행이 없으면 지킴이가 강제로 다시 띄운다
  (활동 로그: "응답 없음(멈춤) → 강제 재시작"). 큰 파일 전송·압축 중에는 진행 표시를 계속 보내 잘못 끊지 않는다.
- **화면을 새 창으로**: 카드의 "화면"이 별도 창(`/?screen=PC번호`)으로 열려 Manager와 동시에 쓸 수 있다. PC마다 창 하나.
  팝업이 막혀 있으면 지금처럼 안에서 열리고, 화면 창의 [새 창으로]로 언제든 옮길 수 있다. 창을 닫으면 화면 전송도 바로 멈춘다.

## v1.8 — 관리자 권한 창 조종 (작업 관리자 등)
Windows는 일반 권한 프로그램이 관리자 권한 창(작업 관리자, 설치 프로그램, 관리자 터미널 등)에 클릭·키를 보내는 것을
조용히 막는다(UIPI). 그래서 그런 창이 앞에 오면 조종이 안 되는 것처럼 보인다.
- 앞 창이 관리자 권한이면 화면 창 위쪽에 노란 경고와 [관리자 권한으로 전환] 버튼이 뜬다.
- 전환: 그 PC에 UAC 확인 창이 뜨고 **그 PC 앞에서 '예'를 눌러야 한다**(UAC 창은 원격으로 누를 수 없음 — Windows 보안).
  한 번 하면 작업 스케줄러에 '가장 높은 권한' 로그인 자동 실행으로 등록되고, 다음부터는 관리자 권한으로 뜬다.
  그 PC에서 직접: `python agent.py --install-admin`
- 마우스 버튼이 눌린 채 남던 문제 수정(화면 밖에서 떼도, 창 전환·조종 끄기·닫기 때 모두 해제).
- 여전히 안 되는 것: UAC 확인 창·잠금 화면·Ctrl+Alt+Del 화면(보안 데스크톱).

## v1.7 — 화면 조종 중 클립보드 공유 (글자만)
- 상대 PC에서 복사(Ctrl+C) → 내 PC 클립보드로. localhost·https로 연 경우 자동으로 들어가고,
  http 주소(예: http://192.168.0.10:8000)로 연 경우 브라우저 보안 때문에 화면 아래 [내 PC로 복사] 버튼이 뜬다.
- 화면을 클릭하고 Ctrl+V → 내 PC에서 복사한 글이 상대 PC 클립보드에 들어간 뒤 붙여넣어진다.
- 조종을 켠 동안만, 화면을 보는 본인만. 최대 10만 자. 이미지·파일은 아직 안 됨(파일은 "명령 실행"의 파일 전송 사용).
- 내용은 서버 메모리에만 잠깐 있고 저장되지 않는다. 활동 로그에는 방향과 글자 수만 남는다.
- Windows는 Windows API, Linux는 xclip(또는 xsel)이 필요.

## v1.6 — 리소스: CPU·RAM·GPU 막대
카드의 리소스를 CPU·RAM·GPU 사용률 막대로 표시(60% 이상 노랑, 85% 이상 빨강). RAM은 사용/전체 GB, NVIDIA는 VRAM도.
GPU: NVIDIA는 nvidia-smi, 그 밖의 Windows GPU(Intel·AMD)는 WMI 성능 데이터(작업 관리자와 같은 계산). 10초마다 갱신. 못 읽으면 "-".
에이전트는 자동 업데이트로 새 버전을 받는다.

## v1.5 — 비밀번호 PBKDF2-SHA256 · 에이전트 자동 업데이트 · 터미널 복사/붙여넣기
- **비밀번호**: 모든 계정(admin 포함) PBKDF2-HMAC-SHA256, 반복 60만 번, 계정마다 다른 16바이트 솔트로 저장.
  예전 bcrypt 해시는 다음 로그인 때 자동으로 바뀐다. 코드·설정 파일에 기본 비밀번호(admin1234)가 더 이상 없다 —
  첫 실행 때 무작위 비밀번호를 콘솔에 한 번만 보여 준다. 잊었으면 `python app.py reset-admin [아이디]`.
- **에이전트 자동 업데이트**: 메인 PC의 `agent/agent.py`가 바뀌면 각 PC가 받아서(해시·문법 확인, .bak 백업) 다시 시작. 끄려면 `--no-update`.
  자동 업데이트가 없는 예전 에이전트(Windows)는 화면 창의 [원격으로 업데이트] 버튼으로 한 번만 바꾸면 된다.
- **화면 보기(Windows)**: 추가 설치 없이 동작 — 캡처는 PowerShell(.NET), 입력은 Windows API. 배율(125%·150%) 화면 좌표 보정.
  화면이 안 오면 이유(예전 버전 / 거부 / 캡처 오류)를 화면 창에 표시.
- **터미널**: 선택 후 Ctrl+C(또는 Ctrl+Shift+C) 복사, 선택 없으면 Ctrl+C는 중단. Ctrl+V·Shift+Insert 붙여넣기,
  오른쪽 클릭은 선택 있으면 복사·없으면 붙여넣기(https/localhost에서만). 여러 줄 붙여넣기는 한 줄씩 차례로 실행. 한글 출력 깨짐 수정.
- 서버 실행: `python app.py` (또는 기존처럼 `python -m uvicorn app:app --host 0.0.0.0 --port 8000`).

## v1.4 — 계정별 API 키 보관함
설정 → "내 API 키": 계정마다 키를 여러 개(최대 20) 등록하고 하나를 골라 쓴다. 키마다 이름·모델·사용량(요청 수, 입력/출력 토큰, 오류, 마지막 사용)이 따로 쌓인다.
- 키별 연결 확인, 모델 변경(쓸 수 있는 모델 목록에서 클릭), 이름 변경, 키 교체(사용량 유지), 사용량 초기화, 삭제.
- 저장 위치: `server/api_keys/<아이디 해시>.json` (Fernet 암호화, 화면에는 앞뒤 일부만). 이 폴더는 `.gitignore` 대상.
- 예전 버전에서 DB에 넣어 둔 키는 처음 열 때 "기본 키"로 자동으로 옮겨지고 DB에서는 지워진다.
- 계정을 삭제하면 그 계정의 키 파일도 지워진다. 다른 계정의 키는 보이지도, 바꿀 수도 없다.
- 화면 보기·조종, 명령 실행, 터미널은 Claude API를 쓰지 않는다(토큰 0). 토큰은 AI 명령·AI 대화에서만 쓰인다.

## v1.3 — 화면 보기·조종
카드의 "화면" 버튼(에이전트가 켜진 PC, operator 이상): 그 PC 화면을 실시간(약 8fps, JPEG)으로 보고, "조종"을 켜면 마우스·키보드를 보낸다.
- 보는 사람이 있을 때만 에이전트가 화면을 올린다. 창을 닫으면 몇 초 안에 멈추고, 서버는 PC당 최신 프레임 1장만 메모리에 둔다.
- 필요 모듈(mss, pillow, pynput)은 에이전트가 처음 쓸 때 자동 설치를 시도한다. pynput이 안 되면 보기 전용.
- 한글: 보는 쪽 입력기로 조합한 글자를 통째로 보낸다. 전체 화면 지원. 주 모니터만.
- 보안: 자기 계정 PC만(다른 계정은 404), viewer 권한 불가, 원격 접속을 끄면 즉시 중단, 조종은 화면을 보는 본인만.
  상대 PC의 에이전트 창에 "'계정' 계정이 이 PC 화면을 보고 있습니다"가 표시되고, 활동 로그에 보기 시작·조종이 남는다.
- 그 PC에서 화면 보기를 아예 막으려면 에이전트를 `--no-screen`으로 실행.
- 제한: Ctrl+Alt+Del·로그인 화면·관리자 권한 창(UAC)은 조종 불가. Linux는 X11 세션 필요(Wayland 불가).
- 본인 소유이거나 사용 허락을 받은 PC에서만 쓸 것.

## v1.0 — AI 대화 권한 모드
대화마다 **수동/자동** 모드. 수동은 모든 명령을 승인 카드로 묻는다. 자동은 안전한 명령을 바로 실행하되, 다음은 자동이어도 항상 묻는다:
삭제·포맷, 종료·재부팅, 프로그램 설치, 인터넷에서 받기, 레지스트리·계정·보안 설정, 서비스·프로세스 종료, 이동·이름 변경, 동적 코드 실행,
Claude가 위험(high)으로 표시한 명령, **허용 폴더 밖 경로**. 허용 폴더는 대화별(기본 ~/pcmanager), 상단 칩으로 추가·해제하거나
카드의 "폴더 허용 후 실행"으로 추가. Claude는 request_folder_access 도구로 먼저 허가를 요청할 수 있다. 카드에 승인이 필요한 이유 표시.
화면: 사이드바 고정, 대화는 대화 영역 안에서만 스크롤.

## v0.9 — AI 대화 탭

## 알아둘 것
- 에이전트는 시스템 프록시를 무시하고 서버에 직접 붙는다. 토큰은 PC별이며 다른 PC의 명령 결과를 조작할 수 없다.
- 받은 파일은 `~/pcmanager/inbox/` 밖으로 나가지 않으며 SHA-256으로 검증한다. 100MB 제한.
- 전송 구간은 아직 HTTP(LAN 내부 전제). TLS는 2차.
- 에이전트가 꺼진 채 보낸 명령은 "대기 중"으로 남는다 — 2차에서 만료 처리 예정.
